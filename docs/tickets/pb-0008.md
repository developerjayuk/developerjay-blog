# PB-0008 — Harden server-only boundaries

- **Scope / acceptance criteria (one testable concern: server-only modules fail loudly, not
  silently, if ever pulled into a client bundle):**
  - `import "server-only";` added to `lib/supabase/server.ts` (cookie-aware session client — the
    highest-value add, since `queries.ts` and the `(protected)` layout/login actions all sit on
    top of it) and `lib/posts/queries.ts` (should carry its own guard rather than relying on
    `server.ts`'s transitively).
  - `import "server-only";` added to `lib/markdown/render.ts` (pulls in Shiki's Node-only theme
    data — today an accidental client import would either silently bloat the client bundle or
    fail with a confusing bundler error instead of Next's clear "This module cannot be imported
    from a Client Component" message).
  - Explicitly out of scope: `lib/markdown/rehype-copy-button.ts` (a pure unified/rehype
    transform, no Node-only API — leave as-is); `lib/auth/admin-email.ts` and
    `lib/auth/sanitize-redirect.ts` (used from `proxy.ts`/middleware, which isn't a client-bundle
    target the same way — adding the guard there needs to first confirm it doesn't break the
    middleware/edge runtime, so it's a separate judgment call, not a drive-by include).
  - AC: `npm run build` still succeeds after adding the guards; a scratch `"use client"` component
    that imports one of the guarded modules fails the build with `server-only`'s error, confirming
    the guard is live (then revert the scratch component).
- **Per-ticket context:** raised from the [PB-0005 PR #4 review](../../.claude/code-reviews/pr-4-review.md)
  — `lib/supabase/admin.ts` is the only module in `lib/` with this guard today; everything else
  that assumes a server context doesn't carry it. Defense-in-depth only — nothing has actually
  leaked to the client.
- **Files touched (estimate):** `lib/supabase/server.ts`, `lib/posts/queries.ts`,
  `lib/markdown/render.ts` — one import line each.
- **Rough size:** tiny, <10 lines of repo changes.
- **Depends on:** PB-0005 (the modules being guarded).
