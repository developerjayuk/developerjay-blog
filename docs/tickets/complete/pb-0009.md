# PB-0009 — Navigation & chrome polish

- **Scope / acceptance criteria (one testable concern: site chrome — header, footer, and
  in-page navigation — is consistent across the public and admin sections, with no
  destructive dead-ends):**
  - Post detail page (`posts/[slug]`) gets a "← Back to posts" link to `/`, shown both above
    the content and below it.
  - The public header ("Developer Jay's Musings" + theme toggle) is extracted into a shared
    `SiteHeader` component and reused on admin pages (`admin/(protected)/*` and
    `admin/login`), not just the public site — so the admin section isn't visually
    disconnected from the rest of the blog.
  - The logout button moves out of the admin dashboard page and into `SiteHeader`, shown only
    when the viewer has an active admin session (`showLogout` passed by the already
    session-gated `(protected)` layout — no extra auth check added to the shared header, since
    that would force the statically-generated `posts/[slug]` route into dynamic rendering).
  - The post edit form gets a "Cancel" link (same style as the back links) back to
    `/admin/posts`, gated behind a `confirm("Are you sure? Any changes have not been saved!")`
    prompt so an in-progress edit isn't lost by an accidental click. Create-mode is unaffected.
  - A minimalist footer (`© {current year} Developer Jay`) renders on every page via the root
    layout — the year is computed with `Date().getFullYear()`, not hardcoded, so it never needs
    a manual update.
  - The theme toggle button swaps its "Light mode" / "Dark mode" text labels for
    `remixicon-react`'s `SunFoggyFillIcon` / `MoonFoggyFillIcon`, keeping the existing
    `aria-label="Toggle theme"` for accessibility.
  - AC: `npm run lint`, `npx tsc --noEmit`, and `npm run build` all pass; `posts/[slug]` still
    prerenders as SSG (`●`) in the build output, confirming the header/footer additions didn't
    regress the ISR strategy.
- **Per-ticket context:** a small batch of UX polish requested ad hoc after PB-0005/PB-0006/
  PB-0008 shipped — no PRD section covers it directly; folded into one ticket after the fact
  since all the changes landed together in one session and share the same "consistent,
  no-dead-end navigation" concern.
