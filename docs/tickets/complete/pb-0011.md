# PB-0011 — Vitest setup + unit/component tests for lib utilities and client components

- **Scope / acceptance criteria (one testable concern: the app's pure logic and interactive
  client components have a fast, repeatable automated test suite, runnable with `npm test`):**
  - **Tooling:** Vitest, React Testing Library (`@testing-library/react`,
    `@testing-library/user-event`, `@testing-library/jest-dom`) and jsdom added as dev
    dependencies. There's a `vitest.config.ts` at the repo root that:
    - resolves the `@/*` → `./src/*` path alias from `tsconfig.json`;
    - uses the React plugin for JSX;
    - defaults to the `jsdom` environment, with a shared setup file that registers the
      jest-dom matchers and runs RTL `cleanup` after each test.
  - **npm scripts:** `test` (`vitest run`, single pass, for validation/CI) and `test:watch`
    (`vitest`, for local dev) added to `package.json`.
  - **Test file convention:** tests sit next to their source as `<name>.test.ts(x)`, e.g.
    `src/lib/posts/slugify.test.ts` or `src/app/(public)/SearchBar.test.tsx`. No top-level
    `tests/` dir.
  - **Lib utility tests** (pure functions, no mocks):
    - `slugify`: lowercases; collapses runs of non-alphanumerics to a single `-`; trims leading
      and trailing dashes; returns `""` for all-symbol input.
    - `sanitizeRedirect`: the open-redirect guard. It passes through valid relative paths
      (including a query string) and falls back to `/admin/posts` for `null`, `undefined`, `""`,
      absolute URLs (`https://evil.com`), protocol-relative (`//evil.com`) and backslash-prefixed
      (`/\evil.com`) values.
    - `isSvgUrl`: `true` for `.svg` paths, case-insensitive; `false` for raster extensions, for
      `.svg` that appears only in the query string, and for unparseable URLs (no throw).
    - `getAdminEmail`: returns `ADMIN_EMAIL` when set. Throws when unset, so a missing env var
      can't make the allowlist check pass everyone through. The env var must be stubbed and
      restored per test.
  - **Client component tests** (RTL + jsdom; `next/navigation`, `next-themes` and the
    `"use server"` `./actions` module are mocked):
    - `SearchBar`: initial value comes from the `q` search param. Typing calls `router.replace`
      with the updated `q` only after the 300ms debounce (fake timers), not on every keystroke.
      Clearing the input removes `q`. Other existing params (e.g. `tag`) are preserved.
    - `TagFilter`: renders nothing for an empty `tags` list. Clicking an inactive tag sets `tag`
      and clicking the active tag removes it, both via `router.replace`. The active tag has
      `aria-pressed="true"`.
    - `TagList`: renders one item per tag and nothing for an empty list.
    - `PostCard`: links to `/posts/<slug>`; renders the title, the excerpt (only when present),
      the tags, and the published date formatted `en-GB` (e.g. "21 August 2026"). The cover image
      gets `dark:invert` only when it's an SVG.
    - `Listbox`: the hidden input carries `defaultValue`. Clicking the button opens the listbox
      (`aria-expanded`). Clicking an option commits it (hidden input + button label update, list
      closes). Keyboard: ArrowDown/ArrowUp move the active option, Enter commits, Escape closes
      without committing. A mousedown outside the listbox closes it.
    - `DeleteButton`: when `confirm` returns `false`, the form submit is prevented; when it
      returns `true`, the submit goes through. `window.confirm` is stubbed and `./actions` mocked.
    - `PostForm`:
      - In create mode, typing the title auto-fills the slug via `slugify`. Once the slug has
        been hand-edited, the title no longer overwrites it.
      - In edit mode, fields are pre-filled from `post`, the slug isn't auto-derived, and the
        hidden `id`/`currentSlug`/`currentStatus` inputs are present.
      - The Cancel link shows only in edit mode, and navigation is prevented when `confirm`
        returns `false`.
      - An `{ error }` action state is rendered.
    - `ImageUpload`:
      - Files over 4MB are rejected client-side with the "4MB or smaller" message and never
        `fetch`ed.
      - On a successful upload (`fetch` stubbed), `onUploaded` is called with the returned URL.
      - A non-ok response with `{ error }` shows that error.
      - A network failure shows the generic "Upload failed" message.
    - `ThemeToggle`: clicking calls `setTheme` with the opposite of `resolvedTheme`, and it keeps
      `aria-label="Toggle theme"`.
    - `MarkdownContent`: clicking a `[data-copy-button]` inside a `[data-code-block]` writes that
      block's `<code>` text to `navigator.clipboard` (stubbed) and switches the button's
      `aria-label` to "Copied". Clicks elsewhere don't copy.
  - **CLAUDE.md updated:**
    - The "Verify" working principle drops "No test suite yet… don't add tests speculatively".
      The new rule: new lib utilities and interactive client components come with Vitest tests
      next to their source; `npm test` joins lint/`tsc`/build as a validation gate; a manual
      browser check is still expected for UI flows.
    - `npm test` / `npm run test:watch` added to Commands.
  - **Explicitly out of scope:**
    - Markdown pipeline (`renderMarkdown`, `rehypeCopyButton`), server actions, the upload Route
      Handler, `queries.ts`, and GitHub Actions CI: all in [PB-0012](pb-0012.md).
    - Async Server Components (`page.tsx`/`layout.tsx` files) and `proxy.ts`: Vitest + RTL can't
      meaningfully render them. They're deferred to a possible future E2E ticket (e.g.
      Playwright); no E2E tooling is added here.
    - Coverage reporting/thresholds.
  - **AC:**
    - `npm test` passes, with every file listed above covered.
    - `npm run lint`, `npx tsc --noEmit` and `npm run build` still pass. The test files and
      `vitest.config.ts` are lint- and type-clean, and nothing test-only leaks into the Next build.
    - `posts/[slug]` still prerenders as SSG (`●`).
- **Per-ticket context:** first automated tests in the repo. Until now CLAUDE.md said to verify
  by hand in the browser and not to add tests until the prototype was stable. The MVP
  (PB-0001–PB-0010) has shipped, so that condition is now met. Split from PB-0012 to keep each
  ticket within one PIV loop. This ticket sets up the test infrastructure and the conventions
  (colocation, mocking `next/navigation`, stubbing `confirm`/`fetch`/`clipboard`) that PB-0012
  builds on.
  - **Known gotchas for planning:**
    - `DeleteButton` and `PostForm` import `./actions` (`"use server"`), which pulls in
      `lib/supabase/server.ts`. That module imports `server-only` and `next/headers`, so the
      component tests must `vi.mock("./actions")` rather than let it resolve.
    - `jsdom` doesn't implement `window.confirm` or `navigator.clipboard`, so both must be
      stubbed.
    - `next/image` inside `PostCard` may need mocking or a check that it renders under jsdom.
    - Server-only modules aren't imported by anything in this ticket's scope; if one is, the
      plan should handle `server-only` in the Vitest config rather than per test.
