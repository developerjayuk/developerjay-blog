# PB-0012 — Server-side tests (markdown, actions, upload route, queries) + GitHub Actions CI

- **Scope / acceptance criteria (one testable concern: the server-side logic behind publishing
  and rendering posts is covered by the Vitest suite, and every push/PR runs lint + type-check +
  tests automatically):**
  - **Test environment:** server-side test files run in Vitest's `node` environment, not jsdom.
    Use a per-file `// @vitest-environment node` docblock or a Vitest `projects` split; the plan
    picks one and documents it. `server-only` resolves to an empty module under Vitest, set once
    in `vitest.config.ts` rather than mocked in every test, so `render.ts`, `queries.ts` and
    `lib/supabase/*` can be imported.
  - **Markdown pipeline tests** (real `unified`/Shiki, no mocks):
    - `rehypeCopyButton` (on a hand-built hast tree): every `<pre>` gets wrapped in a
      `div[data-code-block]` with a `button[data-copy-button][aria-label="Copy code"]` as its
      first child. Non-`pre` elements are left alone.
    - `renderMarkdown`:
      - GFM output works (a table and a strikethrough render).
      - A fenced code block with a language comes out highlighted (`--shiki-light`/
        `--shiki-dark` CSS variables present) and wrapped with the copy button.
      - A code block with no language falls back to plaintext without throwing.
      - Raw HTML in the markdown (e.g. `<script>`, `<img onerror>`) is stripped, not passed
        through. This is the safety guarantee `MarkdownContent`'s `dangerouslySetInnerHTML`
        relies on.
  - **Server action tests** (`app/admin/(protected)/posts/actions.ts`; `lib/supabase/server`,
    `next/cache` and `next/navigation` mocked):
    - `createPost`:
      - A missing/blank title, an invalid status, and a title that slugifies to empty each
        return the matching `{ error }` without calling Supabase.
      - Fields are parsed correctly: tags split on commas and trimmed with empties dropped;
        blank excerpt and cover image URL become `null`; the slug comes from the title when the
        slug field is blank.
      - A `23505` insert error returns the "slug is already in use" message; any other insert
        error returns the generic message.
      - On success it redirects to `/admin/posts`. The `redirect` mock is asserted; the real
        `redirect` throws `NEXT_REDIRECT`.
      - `revalidatePath` is called for `/` and `/posts/<slug>` only when the status is
        `published`.
    - `updatePost`:
      - A missing `id` returns an error.
      - Same validation and `23505` handling as `createPost`.
      - Revalidates when the post was or becomes published.
      - A slug change on a published post also revalidates the old `/posts/<currentSlug>`.
      - A draft-to-draft edit doesn't touch the public paths.
    - `deletePost`:
      - A missing `id` throws.
      - A Supabase error is rethrown.
      - It always revalidates `/admin/posts`.
      - It revalidates the public paths only when the deleted post was published.
  - **Upload Route Handler tests** (`app/admin/(protected)/posts/upload/route.ts`;
    `lib/supabase/server`, `lib/supabase/admin` and `ADMIN_EMAIL` mocked; real `Request`/
    `FormData`/`File`):
    - A cross-origin `Origin` header returns 403 before any auth lookup.
    - No session, or a session with a non-admin email, returns 401.
    - A missing file returns 400.
    - A disallowed MIME type (e.g. `application/pdf`) returns 400 with the "Unsupported file
      type" message.
    - A file over 4MB returns 400.
    - A Storage upload error returns 500.
    - On success it uploads to `post-images` under `<uuid>.<ext>`, with the right extension for
      each allowed type including SVG, and returns `{ url }` from `getPublicUrl`.
  - **Query tests** (`lib/posts/queries.ts`; `lib/supabase/public` mocked with a chainable query
    builder):
    - `getPublishedPosts()` with no filters applies neither `textSearch` nor `contains`.
    - `{ search }` calls `textSearch("search_vector", …, { type: "websearch", config: "english" })`.
    - `{ tag }` calls `contains("tags", [tag])`.
    - Results are ordered by `published_at` descending.
    - A Supabase error is thrown.
    - `getAllTags` de-duplicates and sorts tags across posts.
    - `getPublishedPostBySlug` returns `null` for no match.
  - **GitHub Actions CI:** a new `.github/workflows/ci.yml` runs on push to `main` and on pull
    requests:
    - `npm ci`, then `npm run lint`, `npx tsc --noEmit` and `npm test`.
    - Node LTS (≥ 20.9, which Next 16 requires), with npm caching.
    - No Supabase secrets are needed. `npm run build` is deliberately **not** run in CI:
      `generateStaticParams` queries the live Supabase project at build time, and Vercel already
      builds on every deploy.
  - **CLAUDE.md updated:** Commands (or Verify) notes that CI runs lint + `tsc` + tests on
    push/PR, and that the server-side test environment and `server-only` handling live in
    `vitest.config.ts`.
  - **Explicitly out of scope:**
    - Async Server Components (`page.tsx`/`layout.tsx`) and `proxy.ts`, which are still deferred
      to a possible future E2E ticket.
    - Hitting a real Supabase instance (local or remote): all Supabase access is mocked.
    - Coverage reporting/thresholds.
    - Running `npm run build` in CI.
  - **AC:**
    - `npm test` passes with every module above covered.
    - `npm run lint` and `npx tsc --noEmit` pass.
    - The CI workflow runs green on the PR that introduces it.
- **Per-ticket context:** second half of the test-suite work, split from
  [PB-0011](pb-0011.md). This half holds the tests that need heavier mocking (Supabase query
  builders, `next/cache`, `next/navigation`'s throwing `redirect`, a Node request environment),
  plus CI. The existing validation in the `lib/supabase/*` layer is worth pinning down with
  tests because it's security-relevant:
  - the upload route's CSRF/Origin check and auth re-check, written because Route Handlers
    don't get Server Actions' automatic Origin check;
  - `render.ts`'s "no raw HTML" guarantee.
  - **Known gotchas for planning:**
    - Shiki's first highlight is slow. `renderMarkdown` tests may need a longer per-test
      timeout, or should share one warm processor (the module-level `processor` already does).
    - `lib/supabase/server.ts` calls `cookies()` from `next/headers`. Mock the module itself
      rather than `next/headers`.
    - `queries.ts` wraps its functions in React `cache()`. Check that it doesn't memoize across
      tests outside a request scope, or mock `react`'s `cache` as identity if it does.
